# Аудит путей и переходов «Между уроками» (этап 1)

Дата: 27.09.2026. Ветка `claude/ecstatic-rubin-eloj67` (коммит `450dbbf`). Только смотрели — код не менялся.

## Как проверяли

- **Живые пути (Playwright, Chromium)** — пять ролей на 375 и 1280 px, светлая тема, плюс тёмная тема ключевых экранов:
  1. новый репетитор без аккаунта (главная → студия → вход → кабинет → тренажёр из материалов и из библиотеки → публикация → ученики → курс → задание → оплата → выход);
  2. ученик по ссылке (имя → занятие → «Готово» → профиль → Telegram → курс → урок → «Закрепить» → «назад»), библиотека ЕГЭ, главная ↔ приложение;
  3. родитель (вход → «Кто вы?» → код ребёнка → отчёт → оплата; старая ссылка `/parent/`);
  4. аккаунт с тремя ролями: кабинет ↔ студия ↔ тренажёр ↔ вход ↔ главная, «назад/вперёд», перезагрузка на 30 глубоких и несуществующих адресах;
  5. сервер не отвечает (мок остановлен по PID) и полный офлайн с service worker.
- **Обход всех ссылок и кнопок**: 8 ролей (гость, гость с черновиком, репетитор, ученик по ссылке, ученик библиотеки, родитель, три роли сразу, новый аккаунт), 57 страниц/адресов, **1283 элемента** на 375 и 1280. Для каждого — чистое состояние страницы → нажатие → куда ведёт, тип перехода, время, запросы, ошибки консоли и сети, осталась ли модалка, пустой экран, вечная «Загрузка», вернула ли «Назад» на тот же экран, работает ли перезагрузка адреса назначения. Итог: 346 переходов внутри страницы (#), 278 полных загрузок, 10 загрузок с редиректом, 113 окон, 74 смены экрана без смены адреса (занятия), 62 новые вкладки, 12 скачиваний файлов.
- **Скорость на медленной сети**: 28 ключевых переходов на 375 px в режиме «Fast 3G» (562 мс задержки, 1,44 Мбит/с вниз, 675 кбит/с вверх, gzip как у Cloudflare, заголовки кэша как у Cloudflare), три режима: холодный (пустой кэш), повторный (HTTP-кэш), повторный с service worker.
- **Окружение**: `worker/worker.js` в моке с KV в памяти (Gemini, Telegram, ЮKassa — заглушки). Пути 1–5 — статика `:8080` + API `:8798` (разные адреса, как в инструкции). Обход и замеры скорости — на прод-подобном адресе `:8090/:8092`, где статика и API на одном адресе, как в Cloudflare (иначе нельзя проверить service worker и урезанную библиотеку ЕГЭ).
- **Ограничения**: ИИ (Gemini) не вызывался по-настоящему — ошибки ИИ смоделированы (500, 429, обрыв связи). Оплата — заглушка ЮKassa. Реальные Telegram, Яндекс ID, VK, Google не открывались. Время в таблице обхода — локальное (без сети), реальная картина — в разделе «Что тормозит». Путь 5 (без сети) и замеры скорости — только на 375 px (телефон). Замер «повторно+SW» не учитывает байты, которые качает сам service worker.

Скрипты и материалы (в scratchpad сессии, в репозиторий не входят): `…/scratchpad/audit/` — `j1-tutor.cjs … j5b-offline-sw.cjs`, `crawl.cjs`, `perf.cjs`, `focused.cjs`, `results/*.json`; контактные листы скриншотов — `audit/sheets/*.png` (по пути и по ширине, плюс `dark-*.png`, `crawl-pages-*.png`, `focused.png`).

## Коротко

- **Консоль почти чистая**: при обычных переходах ошибок JavaScript нет, 5xx нет. Ошибки в консоли — только ожидаемые 4xx (неверный код, чужой платёж, несуществующий набор) и прерванные загрузки шрифтов на JS-редиректах. Значит, «много ошибок при переходах» — это **поведение**, а не падения: экраны перерисовываются и стирают ввод, окна висят поверх другой страницы, «Назад» уводит не туда, прокрутка остаётся внизу, на телефоне пропадают нужные ссылки, без сети — вечная «Загрузка».
- **Что работает хорошо**: перезагрузка на всех 30 проверенных глубоких адресах открывает тот же экран (кроме несуществующих — там понятная ошибка); в обходе «Назад» после 634 переходов по ссылкам вернул на тот же адрес и экран в 622 случаях (8 — особенности самого обхода, 4 — главная → «Попробовать» → «Назад» показывает тренажёр вместо главной, № 11), перезагрузка адреса назначения — 264 из 264 без ошибок; «назад/вперёд» по экранам ученика и вкладкам кабинета возвращает туда же; переходы внутри страницы (экраны ученика, вкладки студии и кабинета) — мгновенные даже на 3G; без сервера ученик занимается по сохранённому набору, а студия честно пишет «не сохранено»; тёмная тема без явных провалов контраста.
- **Найдено 38 проблем**: блокер — 3, мешает — 24, косметика — 11.
- **Скорость**: на мобильной сети каждый переход между страницами (главная ↔ студия ↔ кабинет ↔ вход ↔ тренажёр) — это полная загрузка страницы: **1,7–2,4 с до первого экрана даже с тёплым кэшем**, данные в кабинете и студии появляются и перестают меняться через **4–6 с**, библиотека ЕГЭ — 3,7–4,3 с. Переходы внутри страницы — 1–15 мс. Время съедают круги запросов, а не объём: каждый файл перепроверяется на сервере, модули грузятся цепочкой, запросы к API идут друг за другом. Service worker (сеть → кэш) при наличии сети не ускоряет ничего.

**Топ-10 проблем:**
1. Студия после синхронизации с облаком перерисовывает экран и **стирает вставленный материал** (медленная сеть) — `studio/studio.js:53-64`. (№ 1)
2. Без сети service worker отдаёт `index.html` вместо студии/кабинета/`/parent/` → **вечное «Загружаю…»**; вход и оферта показывают чужой экран — `sw.js:31-35`. (№ 2)
3. У ученика плитки **«undefined»** в сетке «Задания ЕГЭ», если репетитор смешал свои темы и темы библиотеки — `app.js:579-590`. (№ 3)
4. Окна не закрываются по «Назад»/смене адреса/Esc и **висят поверх другого экрана** — `lib.js:185-193`. (№ 4)
5. «Попробовать» в студии: кнопка «→» под крестиком — **нажатие закрывает просмотр** — `studio/studio.js:170-172`, `app.css:358,365`. (№ 5)
6. «Открыть как ученик» **записывает репетитора в его же ученики** и тратит одно из 3 бесплатных мест — `app.js:995-1003`. (№ 6)
7. На телефоне **из студии нет пути в кабинет** (имя в шапке скрыто) — `app.css:797`. (№ 7)
8. После «Выйти» тренажёры и ключи остаются в браузере, а SW хранит ответы API с именами учеников — `studio/studio.js:88-93`, `sw.js:24-27`. (№ 8)
9. У занятия нет адреса: **«Назад» телефона выкидывает ученика из тренажёра** посреди занятия — `app.js:663-788`. (№ 9)
10. CSS перебивает `hidden`: после выбора Telegram не прячутся остальные способы входа, в редакторе карточки видны сразу «Варианты» и «Ответ» — одна строка в `app.css`. (№ 10)

### Что видит новый репетитор (телефон, мобильная сеть)

**Честный итог:** за 2 минуты репетитор понимает обещание — главная написана хорошо и про его боли — и может получить ссылку для учеников. Но **ни одну из трёх главных выгод он не видит в самом продукте**: отчёт и «кто занимался» есть только картинкой на главной, а в студии и кабинете у новичка пусто. Путь к ссылке рабочий, но с отвлечениями: предупреждение о входе, тариф и «Оплатить» в пробный период, «Подключить Telegram», шесть вкладок у тренажёра («Курс» и «Настройки» новичку пока не нужны), пустые черновики после «Создать тренажёр».

### Три боли, которые мы реально снимаем, и где это видно

1. **«Ученики не занимаются между уроками, и я не знаю, кто занимался».**
   Видно: вкладка тренажёра «Ученики» — сводка «учеников · занимались за неделю · карточек за неделю», по каждому: был(а), 14 квадратиков активности, точность, задание, слабые темы, блок «Что разобрать на уроке» с кнопкой «Скопировать план урока»; кабинет → «Требуют внимания» (не занимается N дней / точность ниже 60 %); задание со сроком и напоминания ученикам в Telegram.
   Спрятано: у новичка всё пусто; на телефоне таблица обрезана (№ 13); «Требуют внимания» — в кабинете, а из студии в кабинет на телефоне ссылки нет (№ 7).
2. **«Родители спрашивают, есть ли прогресс».**
   Видно: «Ученики» → «Отчёт» (готовый текст для родителя и «Скопировать»); карточка ученика → «Отчёты родителю в Telegram» (каждое воскресенье); кабинет родителя (дни занятий, точность по неделям, слабые темы).
   Спрятано: «Отчёт» — в последней колонке широкой таблицы (на телефоне за экраном); кабинет родителя требует, чтобы ученик вошёл в аккаунт и выдал код («Ученик ещё не вошёл в аккаунт…»); еженедельный отчёт в Telegram — самый удобный вариант — спрятан в карточке ученика. За первые 2 минуты не виден совсем.
3. **«Нет времени собирать тренажёры, материалы разбросаны».**
   Видно: «Создать тренажёр» сразу открывает «Добавить» → «Из ваших материалов» (текст, PDF, фото → ИИ → проверка → добавление), «Из библиотеки» (≈ 3000 заданий ЕГЭ и олимпиад), «Похожие» (ИИ делает варианты карточки), «Готовый пример за 1 клик».
   Это единственная выгода, которую можно пощупать в первые минуты, и путь к ней короткий. Риски: при ошибке ИИ непонятно, что делать (№ 26); на медленной сети вставленный текст стирается (№ 1); у ученика «undefined» вместо своих тем, если смешать свои темы и библиотеку (№ 3).

### Что упростить в первом пути (предложения для этапа 2)

1. **Один следующий шаг на экране.** После входа — только «Создайте первый тренажёр» с двумя крупными вариантами: «Из своих материалов» и «Готовые задания ЕГЭ». Тариф, Telegram, «Импорт из файла», вкладку «Курс» — показывать после первой публикации.
2. **Пример, который показывает пользу, а не список карточек.** «Готовый пример» открывается глазами ученика (как живая карточка на главной), а рядом — «Ученики» с тремя демо-учениками с пометкой «пример»: активность, слабые темы, «Отчёт родителям» с готовым текстом. Тогда все три выгоды видны в первую минуту. Пример — по предмету репетитора (русский / математика / экономика / свой) и маленький (отдельный файл, а не вся библиотека на 1,6 МБ).
3. **Публикация без обрыва.** Если нужен вход — войти и сразу опубликовать (сейчас после входа снова нажимать «Опубликовать», `studio/studio.js:1162-1165`). После публикации — крупная карточка «Отправьте ссылку ученикам»: «Скопировать», «Отправить в Telegram», QR. «Открыть как ученик» — просмотр без записи в ученики.
4. **Одна шапка и один кабинет репетитора.** Кабинет и студия — одна страница с вкладками «Тренажёры · Ученики · Настройки»; «Требуют внимания» — сверху в «Учениках». Нет полных перезагрузок между ними и нет потерянных ссылок на телефоне.
5. **Главная ведёт репетитора в продукт репетитора.** «Попробовать» → пример в студии; у вошедшего вместо «Войти» — «Кабинет».
6. **«Ученики» на телефоне — карточками**: имя, был(а), точность, кнопки «Отчёт родителям» и «Ошибки» сразу видны. Еженедельный отчёт в Telegram — предлагать прямо там, а не в глубине карточки.

Оговорка: полный набор ЕГЭ для вошедших (строки «Добавить → библиотека», «Готовый пример») мок отдаёт без ETag, поэтому «повторно» он скачивается заново; в Cloudflare у статики есть ETag, и повторно придёт 304. Бесплатная часть ЕГЭ (`no-store`) и набор репетитора (без ETag) и в проде скачиваются каждый раз.

Внутри одной страницы (хэш-переходы ученика: главная → профиль, курс → урок, начало занятия; вкладки студии и кабинета) всё быстро: 1–15 мс до первого экрана, дольше только там, где ждут API (профиль ученика — 0,6 с на `/notify`).

### Почему медленно

1. **Каждый переход между страницами — полная загрузка**: главная, студия, кабинет, вход, тренажёр ученика — отдельные HTML-страницы. Каждая заново проходит цепочку: HTML → `app.css` + `config.js` + модуль → модули `lib.js`, `account.js` (о них браузер узнаёт только после загрузки первого модуля) → запросы к API → отрисовка. На 3G это 4–5 кругов по 0,56 с, поэтому **1,7–2,4 с до первого экрана даже с тёплым кэшем**: файлы не перекачиваются (2–4 КБ), но каждый перепроверяется на сервере (`max-age=0, must-revalidate`).
2. **Service worker не ускоряет**: стратегия «сначала сеть, потом кэш» (`sw.js:22-35`) при наличии сети ждёт ту же сеть — цифры «повторно» и «+SW» почти одинаковые.
3. **Запросы к API идут цепочкой**: студия — `/me` → `/me/studio` → `PUT /me/studio`; кабинет — `/me` → `/me/studio` → `/packs/<id>/progress` для каждого тренажёра; вход — `/me` до отрисовки. Каждое звено — ещё 0,56 с.
4. **Большие JSON без кэша**: бесплатная часть ЕГЭ (240 КБ gzip, `no-store`) и набор репетитора (`no-cache` без ETag) качаются при каждом открытии; «Готовый пример» тянет всю библиотеку ради трёх тем; кабинет родителя — все наборы ребёнка.
5. **Лишняя работа после открытия**: студия пишет себя в облако (до 100+ КБ вверх, на 3G ≈ 1,3 с) и перерисовывается; «Ученики» и библиотека в студии запрашиваются дважды; главная перерисовывается на якорях.
