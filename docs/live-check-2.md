# Проверка живого сайта после PR #47

Адрес: https://econcards.kqrulev.workers.dev · время: 2026-09-28, 04:10–05:05 UTC · режим `QUICK=1` (без обхода всех кнопок).

Сравнение с `docs/live-check.md` (ветка `claude/live-check`, проверка 27.09.2026 после PR #46). Только чтение: без входа в аккаунты, без POST/PUT, без записей в KV. На сайте service worker `zadachnik-v35` — PR #47 выложен.

## Что закрылось

- **Несуществующая страница — теперь страница сайта, а не JSON.** `/no-such-page` → 404, `text/html`, 2,3 КБ, это `404.html`: заголовок «Такой страницы нет», кнопки «На главную» и «Войти в кабинет» (скрин `shots/nav-375-light/15-несуществующая-страница.png` в папке прогона). Раньше было `application/json` с `{"error":true,"message":"Нет такого адреса."}`. Замечание из прошлого отчёта и № 38 из `docs/audit.md` закрыты. Ответ воркера на неизвестные API-пути не изменился: `/packs/zzzz1234` → 404 JSON, `/me` без входа → 401.
- **Лишних 307 при переходах больше нет.** В выложенных `landing.js`, `account.js`, `studio/studio.js`, `cabinet/cabinet.js`, `app.js` ссылок на `login.html`, `offer.html`, `privacy.html` не осталось (только комментарии). В путях nav и tutor (три прогона, 375 и 1280 px) ни одного ответа 307. Сами адреса `/login.html`, `/offer.html`, `/privacy.html`, `/offline.html`, `/index.html` по-прежнему отвечают 307 на адрес без `.html` — это Cloudflare, и это правильно для старых ссылок.
- **Гость в кабинете уходит на вход сразу.** `/cabinet/` → 200, в `<head>` инлайн-скрипт: нет `zd-session` — `location.replace('../login?next=cabinet/…')` до загрузки кабинета. `/parent/` так же ведёт гостя на `/login?role=parent&next=cabinet/#parent` одним шагом. Шаги nav 08–10 показывают страницу входа с правильным `next`.
- **ИИ в студии только после входа.** В выложенном `studio/studio.js` «Похожие» и карточки из вставленного текста у гостя ведут в окно входа (обе проверки `signedIn()` на месте). В браузере это не воспроизводилось: путь «гость с черновиком» есть только в полном обходе. Попыток записи на сервер за прогон — 0 (раньше было 10, включая `POST /ai ×2`). Оговорка: в `QUICK` нет обхода всех кнопок, где эти попытки и ловились; `POST /auth/*` от кнопок входа в путях тоже не было, потому что пути их не нажимают.

## Скорость: кабинет без входа

Первый экран, мс, 375 px. Цифры «3G» — через прокси-замедлитель облачной среды, сравнивать стоит только строки между собой и с прошлым отчётом.

| Переход | Было: сеть | Стало: сеть | Было: 3G | Стало: 3G | Запросов (3G) |
|---|---|---|---|---|---|
| Кабинет (гость) → вход | 1140 | 638 | 7677 | 4488 | 23 → 20 |
| /parent/ → вход родителя | 1239 | 461 | 8945 | 4388 | 24 → 14 |
| Вход напрямую | 639 | 615 | 4416 | 4349 | 14 → 14 |

- Вход из `/parent/` теперь стоит столько же, сколько прямое открытие `/login`: повторных запросов нет.
- Вход из `/cabinet/` всё ещё грузит `app.css`, `lib.js`, `account.js`, `config.js` дважды. Инлайн-скрипт стоит раньше `<link>`, но сканер предзагрузки Chromium успевает начать эти запросы до `location.replace`. Стоимость небольшая: на повторе это ответы 304, всего 34 КБ. Если хочется убрать совсем, `modulepreload` и `stylesheet` в `cabinet/index.html` придётся вставлять из скрипта после проверки сессии. Это не поломка.
- Остальные строки раздела 5 в пределах прошлого прогона: главная 3G 4,8 с, с service worker 1,4 с; библиотека ЕГЭ 6,2 с при первом открытии, 4,5 с повторно (набор приходит 304).

## Ошибки JS

Новых нет. Уникальные ошибки за прогон те же, что в прошлый раз, и все ожидаемые:

`pageerror` нет ни в одном пути. Пустых экранов, вечной «Загрузки» и 5xx нет. Офлайн в обоих режимах (visited, landing-only) работает как задумано, ответов API в кэше нет.

## Пометки, которые не поломки

Те же, что в прошлом отчёте: «окно висит» в пути репетитора (окна по задумке), шаг 05 «Глазами ученика» (скрипт жмёт под открытым окном), шаг 14 (у гостя в студии ссылки на кабинет нет по задумке). В разделе 1 `http.mjs` по-прежнему считает 4 «проблемами» ответы 307 на `/login.html`, `/offer.html`, `/privacy.html`, `/offline.html`, потому что ждёт 200: это ожидание самой проверки, его стоит поменять на 307 → адрес без `.html`.

## О самой проверке

- Chromium снова не доверял CA прокси среды: сертификаты из `/root/.ccr/ca-bundle.crt` добавлены в NSS-хранилище браузера через `certutil` (пакет `libnss3-tools`), проверка TLS не отключалась.
- Первый замер скорости на «3G» сорвался: старый `throttle-proxy.mjs` из `main` рвёт TLS (`ERR_SSL_PROTOCOL_ERROR`). Правка из ветки `claude/live-check` (куски строго по порядку) перенесена в эту ветку одним коммитом, замер перезапущен, сбоев нет. Код сайта не менялся.
- Папка прогона `tools/audit/out/live-check-2/` (report.md, results, скриншоты) в коммит не входит: она в `.gitignore`.
