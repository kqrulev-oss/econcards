# Три направления интерфейса ученика

Первый этап: выбрать визуальный язык. Изменения находятся **только в `design/`**.
Основные `app.css`, `app.js`, `lib.js`, `sw.js`, конфиги, Worker и наборы не изменены.
После выбора — отдельный PR с переносом в `app.css`, обновлением версии кэша и
пунктами 1–6 исходной задачи. Этот PR не сливать до проверки владельцем / Claude Code.

## Посмотреть

```sh
node tools/dev-server.mjs
```

- Стенд: <http://localhost:8080/design/index.html>
- Стикеры: <http://localhost:8080/design/?design=a>
- Тетрадь: <http://localhost:8080/design/?design=b>
- Приложение: <http://localhost:8080/design/?design=c>
- Реальное приложение: <http://localhost:8080/design/student.html?p=ege-math&design=b>
- Другие наборы: заменить `p` на `ege-phys`, `ege-bio` или `ege-rus`.
- `theme=light` / `theme=dark` — принудительный просмотр темы; без параметра — тема устройства.

Переключатель сохраняет `localStorage['zd-design']`. Параметр `design` имеет
приоритет. `student.html` подключает **существующий корневой `app.js`** через
`<base href="../">`, а `preview.js` сохраняет переходы внутри этой оболочки.
Палитра направления имеет приоритет над цветом набора только в предпросмотре.

Обычный корневой адрес `/?p=ege-math&design=b` намеренно не изменён: подключить
загрузчик к корневой странице в PR, содержащем только `/design/`, невозможно.
Для проверки настоящих экранов предназначен `design/student.html`; подключение
к корневой странице — часть второго PR после выбора.

## Что общее

`index.html`, `app.js`, `shared.css`, загрузка данных и проверка ответов — одни
на все варианты. Направления `app-a.css`, `app-b.css`, `app-c.css` переопределяют
токены `:root` и компоненты. Зависимостей, сборки, внешних шрифтов и скриптов нет.

Четыре экрана идут одним столбцом:

1. Главная математического набора с настоящими названиями заданий.
2. Числовая карточка `ep07-exp-base-1` и её разбор.
3. Соответствие `p-ph-ege-06-change-float-9d05dd1465` из физики.
4. Тренажёр с предметами и метаданными `packs/index.json`.

Карточки загружаются через `fetch` из `packs/ege-math.json` и `packs/ege-phys.json`.
Используется `renderCard` из существующего `lib.js`. Кнопки соответствий — только
адаптер представления над его значениями и проверкой; частичный балл не меняется.
Формулы оформляются поверх DOM, данные набора не переписываются.

Прогресс на главной стенда — явно обозначенный пример: ответы здесь не меняют
прогресс ученика. В `student.html` работает настоящее приложение с обычным
локальным прогрессом.

## Направления

| | Характер | Типографика | Поведение |
| --- | --- | --- | --- |
| A · Стикеры | Контуры, цветные плитки, тени у действий | Unbounded + Nunito | Кнопка опускается при нажатии |
| B · Тетрадь | Бумага, тонкая сетка, спокойные статусы | Georgia + Nunito | Сдержанные состояния без объёмных теней |
| C · Приложение | Плотные карточки, фоновые слои, нижняя панель | Nunito | Переходы 180 мс, свайп между разделами на стенде |

Цвет точности дополнен процентом и символом: `✓`, `≈`, `!`. Значение доступно
без различения красного и зелёного. Учитывается `prefers-reduced-motion`.

## Проверка

Chromium 153.0.8010.0 через Playwright, локальный `tools/dev-server.mjs`.
В окружении нет глобального Chromium; браузер подготовлен отдельно, вне репозитория.

- 3 направления × 2 ширины (375 / 1280) × 2 системные темы: без горизонтального
  переполнения документа.
- Переключение направления, запись выбора и восстановление после перезагрузки.
- Числовой ответ: ввод, Enter, правильный и неправильный ответ, разбор.
- Соответствие: смена выбранного номера, проверка только после заполнения всех
  позиций, оценки 1 / 0,5 / 0, блокировка кнопок после проверки.
- Кнопки соответствий не меньше 44 × 44 px.
- Разделы «Задания / Ошибки / Прогресс», переход к карточке, предметы.
- Реальное приложение: все 4 набора × 3 направления, главная → тема → назад → занятие.
- Вычисленный контраст видимого текста четырёх экранов и образцов состояний:
  нет значений ниже 4,5:1 в проверенных светлой и тёмной палитрах.
- Скриншоты просмотрены: исправлены перенос степени и ширина обозначения «ДНК».
- `node --check` для трёх модулей, `git diff --check`; ошибок JavaScript нет.

Это просмотр в Chromium с мобильной шириной, не проверка на физическом iPhone.
Оценка дальтонизма основана на избыточных обозначениях, а не на пользовательском исследовании.
