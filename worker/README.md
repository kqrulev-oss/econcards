# Сервер «Между уроками» (Cloudflare Worker)

Один маленький Worker делает три вещи:

- **ИИ**: проверяет решения, даёт подсказки и делает карточки из материалов репетитора. Работает на Workers AI (бесплатный тариф Cloudflare, ключ не нужен); Gemini — запасной, если задан ключ.
- **Наборы**: хранит опубликованные тренажёры, ученик открывает их по ссылке `?t=<код>`.
- **Прогресс**: принимает сводки учеников и отдаёт их репетитору по ключу.

На бесплатном тарифе Cloudflare всё это стоит $0 при небольшом числе учеников: Workers AI даёт 10 000 нейронов в день (примерно 100–300 ответов ИИ), дальше до следующего дня сервер отвечает «ИИ исчерпал бесплатную квоту».

## Быстрый способ: одна кнопка

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/kqrulev-oss/econcards/tree/main/worker)

1. Нажмите кнопку и войдите в Cloudflare (регистрация бесплатная). Cloudflare попросит подключить GitHub: он скопирует папку `worker/` в новый репозиторий в вашем аккаунте.
2. Хранилище `DB` и привязка `AI` создадутся сами. Ключ Gemini (`GEMINI_KEY`) — по желанию, как запасной ИИ (шаг 1 ниже).
3. Нажмите **Deploy** и скопируйте адрес вида `https://zadachnik.<аккаунт>.workers.dev`.
4. Впишите этот адрес в `config.js` в корне сайта (шаг 4 ниже).

Ниже — то же самое вручную.

## 1. Ключ Gemini (необязательно, запасной ИИ)
1. Откройте https://aistudio.google.com/apikey — нужен только Google-аккаунт.
2. «Create API key», скопируйте ключ. С мая 2026 ключи начинаются с `AQ.` — это нормально, сервер передаёт их в заголовке `x-goog-api-key`, как требует Google.
3. Не подключайте к проекту оплату (billing): тогда при утечке ключа максимум закончится бесплатная квота.
4. Ключ кладите только в секрет Cloudflare (шаг 3 ниже), не в файлы репозитория и не в `config.js`.

## 2. Хранилище KV
Cloudflare → **Storage & Databases → KV → Create namespace**, например `ZADACHNIK`.

## 3. Worker
1. **Workers & Pages → Create → Worker**, имя `zadachnik`, **Deploy**, затем **Edit code**.
2. Вставьте содержимое `worker.js`, снова **Deploy**.
3. **Settings → Bindings → Add → KV namespace**: имя переменной `DB`, namespace из шага 2.
4. **Settings → Variables and Secrets**:
   - привязка **Settings → Bindings → Add → Workers AI**, имя переменной `AI` (через `wrangler.jsonc` ставится сама);
   - (необязательно) секрет `GEMINI_KEY` — ключ из шага 1, запасной ИИ;
   - (необязательно) `AI_MODEL` — модель Workers AI, по умолчанию `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, при сбое `@cf/qwen/qwen3-30b-a3b-fp8`;
   - (необязательно) `MODEL` — по умолчанию `gemini-flash-latest` (Google сам держит его на актуальной модели), при перегрузке сервер переключается на `gemini-flash-lite-latest`;
   - (необязательно) `DAILY_LIMIT` — ИИ-запросов на IP в сутки, по умолчанию 60.

Через Wrangler то же самое (файл `wrangler.toml` уже лежит в этой папке):
```
cd worker
npx wrangler kv namespace create DB      # выданный id вписать в wrangler.toml
npx wrangler deploy
npx wrangler secret put GEMINI_KEY       # необязательно; ключ вводится в терминале, в файлы не попадает
```

## 4. Подключить
Впишите адрес Worker'а (`https://zadachnik.<аккаунт>.workers.dev`) в `config.js` в корне сайта — тогда он будет у всех учеников. Или только у себя: Студия → «Настройки» → «Сервер».

## Что уходит на сервер
- Проверка и подсказка: условие, эталонное решение, решение ученика.
- Генерация: текст материалов репетитора (до 30 000 символов); PDF и фото сначала распознаются в текст (Workers AI `toMarkdown`), модель получает текст.
- Прогресс: имя ученика, которое он сам ввёл, и сводка — сколько карточек решил, точность по темам, id карточек с ошибками. Сводки хранятся 180 дней.

Смотреть прогресс учеников может только тот, у кого есть ключ набора. Ключ создаётся в браузере репетитора при создании тренажёра и лежит там же, поэтому делайте резервную копию: Студия → «Настройки» → «Скачать набор».

## Telegram-бот: один чат для Claude и Codex

Код — `worker/bot.js`, работает на том же воркере. Вы пишете задачу боту, Gemini
решает, кому она (Codex — дизайн, Claude — логика и данные, Gemini — просто
ответить), и спрашивает подтверждение кнопкой. Бот создаёт issue на GitHub с
`@claude` или `@codex`, агенты делают PR, их ответы и PR приходят в чат.
Ответ реплаем на сообщение агента уходит ему в тот же issue.
Все изменения идут через Claude Code: каждый PR, который открыл не Claude (Codex,
ChatGPT, правки руками), бот сам отдаёт Claude на проверку, а тот доводит его и
пишет, можно ли сливать. Сливаете вы.

Настройка (один раз):

1. **Бот.** В Telegram откройте @BotFather → `/newbot` → получите токен.
2. **Токен GitHub.** github.com → Settings → Developer settings → Fine-grained tokens →
   Generate: Repository access — *Only select repositories* → `econcards`;
   Permissions: **Issues — Read and write**, **Pull requests — Read and write** (чтобы просить Claude проверить PR от Codex).
3. **Секреты в Cloudflare** (Workers → econcards → Settings → Variables and Secrets,
   тип *Secret*): `TG_TOKEN` (из п.1), `TG_SECRET` (любая длинная случайная строка),
   `GH_TOKEN` (из п.2), `GH_SECRET` (другая случайная строка).
4. Откройте `https://<адрес воркера>/tg/setup?key=<TG_SECRET>` — бот подключится.
   Напишите боту `/start`: он пришлёт ваш chat id. Добавьте его секретом `TG_OWNER`
   — теперь бот слушается только вас.
5. **Вебхук GitHub.** Репозиторий → Settings → Webhooks → Add webhook:
   Payload URL `https://<адрес воркера>/gh`, Content type `application/json`,
   Secret — значение `GH_SECRET`, события: *Issue comments*, *Pull requests*,
   *Pull request reviews*.
6. **Режим работы.** По умолчанию бот — пульт задач: пишет issue с пометкой
   `[Claude]` или `[Codex]`. Задачи Claude выполняет Claude Code в приложении
   (напишите ему «возьми задачи из бота»), ТЗ для Codex бот присылает текстом —
   его можно вставить в ChatGPT. Если позже подключите агентов к GitHub
   (приложение Claude + workflow с `anthropics/claude-code-action`, Codex на
   chatgpt.com/codex), добавьте переменную `AGENTS_ON_GITHUB=1` — бот начнёт
   звать их через `@claude` / `@codex` и отдавать чужие PR Claude на проверку.

Команды: `/claude …`, `/codex …` — отдать без выбора, `/ask …` — спросить Gemini,
`/status` — открытые задачи.

## Аккаунты и вход

Код — `worker/auth.js` (сервер) и `account.js` (окно входа на сайте). Вход общий для
репетитора, ученика и родителя; после входа студия и прогресс сохраняются в облаке
(KV) и открываются с любого устройства. Ключи наборов (X-Key) продолжают работать.

- **Telegram** — работает сразу, если бот настроен (`TG_TOKEN`): сайт даёт ссылку
  `t.me/<бот>?start=login_…`, человек жмёт «Start», затем кнопку «Да, это я — войти»
  (кнопка защищает от присланных кем-то ссылок входа).
- **Код на почту, без своего домена** — письма уходят с отдельного ящика Яндекс Почты
  по SMTP (smtp.yandex.ru:465, TLS; код — `worker/smtp.js`). Заведите ящик (например
  `mezhdu.urokami@yandex.ru`) → Настройки → Почтовые программы → разрешить доступ
  почтовым клиентам → id.yandex.ru → Безопасность → Пароли приложений → «Почта».
  Секреты: `SMTP_USER` (адрес ящика) и `SMTP_PASS` (пароль приложения, не от аккаунта).
  Необязательно: `SMTP_HOST`, `SMTP_PORT` для другой почты. Яндекс ограничивает число
  писем в сутки с обычного ящика — для роста нужен свой домен и сервис рассылок.
- **Код на почту, со своим доменом** — нужны секреты `RESEND_KEY` (resend.com → API Keys) и
  `EMAIL_FROM` (например `Между уроками <login@ваш-домен.ru>`). Resend отправляет
  письма только с подтверждённого домена (адрес `*.workers.dev` не подойдёт),
  поэтому включается после покупки домена.
- **Яндекс ID** — oauth.yandex.ru → «Создать приложение» → платформа «Веб-сервисы»,
  Redirect URI `https://<адрес>/auth/yandex/callback`, доступы: «Доступ к логину, имени
  и фамилии», «Доступ к адресу электронной почты». Секреты `YANDEX_ID` (ClientID) и
  `YANDEX_SECRET` (Client secret).
- **VK ID** — id.vk.ru/business/go → «Создать приложение» → тип «Web», доверенный
  Redirect URL `https://<адрес>/auth/vk/callback`, базовый домен — адрес сайта.
  Секрет `VK_ID` (ID приложения); секретный ключ не нужен (OAuth 2.1 с PKCE).
  VK требует подтвердить бизнес-профиль в течение 60 дней после создания приложения.
- **Google** — код есть, но включать не советуем: по 149-ФЗ (с изменениями 406-ФЗ)
  российским сайтам разрешена авторизация через российский номер телефона, Госуслуги
  или российские системы (Яндекс ID, VK ID подходят, Google — нет); к тому же условия
  Google API требуют 18+. Если всё же нужно: console.cloud.google.com → OAuth consent
  screen (External) → **Publish app** (иначе войдут только тестовые пользователи) →
  Credentials → OAuth client ID → Web application, redirect URI
  `https://<адрес>/auth/google/callback`. Секреты `GOOGLE_ID` и `GOOGLE_SECRET`.

Если вы уже вошли одним способом и входите другим, способ привязывается к тому же
аккаунту. Возврат от провайдера идёт только на адрес этого сайта.

Способ входа появляется на сайте, только когда заданы его секреты (`GET /auth/providers`).
Вход через Яндекс/VK/Google завершается только в том браузере, где его начали
(одноразовый `bind`), — чужая ссылка `#login=…` не сработает.

**Все ключи и настройки добавляйте в Cloudflare → Workers & Pages → econcards →
Settings → Variables and Secrets с типом Secret.** Переменные типа Text стираются
при каждом обновлении сайта из GitHub, а раздел Settings → Build → Variables — это
переменные сборки, работающий сайт их не видит. Причины ошибок входа и оплаты видны в
Cloudflare → econcards → Logs (Live).

Ограничение бесплатного Cloudflare KV — 1000 записей в сутки на весь сайт (вход ≈ 7,
сохранение прогресса ученика — не чаще раза в 5 минут и в конце занятия). При росте учеников хранилище
стоит перенести в D1 (100 000 записей в сутки бесплатно).

## Тарифы и оплата (ЮKassa)

Код — `worker/billing.js`. Цены и пробные периоды — переменные Cloudflare (можно менять
без правки кода, тип Secret): `PRICE_TUTOR_1` (790), `PRICE_TUTOR_3` (1990),
`PRICE_LIB_1` (390), `PRICE_LIB_3` (990), `TRIAL_TUTOR_DAYS` (14), `TRIAL_LIB_DAYS` (7).
Сумма платежа сверяется с ценой на момент его создания, так что цены можно менять
в любой момент.

| | Пробный | Без оплаты | По подписке |
|---|---|---|---|
| Репетитор | 14 дней всё | 1 опубликованный тренажёр, до 3 учеников в нём | без ограничений, ученики получают библиотеку ЕГЭ |
| Ученик / родитель | 7 дней полный доступ | теория и 2 прототипа в каждом задании | вся библиотека ЕГЭ |

Проверка на сервере: публикация нового тренажёра требует входа; лимиты бесплатного
тарифа — при публикации и при появлении нового ученика; библиотека `packs/*.json`
без доступа отдаётся урезанной. Наборы, опубликованные до тарифов, не ограничиваются.

Подключение ЮKassa (самозанятый):
1. yookassa.ru → подключиться как самозанятый (по Q&A ЮKassa — независимо от возраста),
   выплаты — на свой счёт 40817… на следующий рабочий день.
2. Интеграция → Ключи API → выпустить секретный ключ (показывают один раз). Секреты
   Cloudflare: `YK_SHOP_ID` (shopId) и `YK_SECRET`. Сначала можно проверить всё на
   тестовом магазине (свои shopId и ключ `test_…`), потом заменить на боевые.
3. Интеграция → HTTP-уведомления: URL `https://<адрес>/pay/webhook`, события
   `payment.succeeded` и `payment.canceled`. Если начислить доступ не удалось, сервер
   отвечает ошибкой, и ЮKassa повторяет уведомление до суток; один платёж продлевает
   доступ один раз.
4. **Чеки.** С 29.12.2025 ЮKassa не передаёт чеки самозанятых в «Мой налог» — чек
   оформляете сами: после каждой оплаты бот присылает сумму, тариф и почту покупателя
   (её спрашивает окно оплаты) → «Мой налог» → «Новая продажа» → отправить чек на почту.
   Раз в месяц сверяйте чеки со списком платежей в кабинете ЮKassa.
5. Возврат: деньги возвращаются в кабинете ЮKassa, чек аннулируется в «Мой налог»,
   доступ снимается командой `/grant <id> lib -30` (отрицательные дни).

Пока ключей нет, кнопка оплаты предлагает написать в Telegram, а доступ выдаётся
командой бота `/grant <id|почта|telegram id> tutor|lib <дней>` (номер аккаунта
человек видит в кабинете → Настройки). `/stats` — сводка по аккаунтам, пробным периодам
и оплатам (тестовые платежи помечены в `paid:<id>` полем `test`).

### Промокоды

Создаются командой бота (только владелец):
- `/promo add START20 скидка 20 any 50 30` — скидка 20% на любой тариф, 50 использований, 30 дней;
- `/promo add LAUNCH14 дни 14 tutor` — +14 дней студии сразу, без оплаты;
- `/promo` — список и сколько раз использован; `/promo off КОД` / `/promo on КОД`.

Каждый аккаунт использует код один раз. Скидка 1–90% (цена не ниже 1 ₽) засчитывается
после успешной оплаты; дни начисляются сразу. Поле «Есть промокод?» — в окне оплаты.

## Уведомления в Telegram

Код — `worker/notify.js`, тот же бот, что и для входа. Всё служебное: без рекламы,
не чаще раза в день, только с 9:00 до 21:00 по времени получателя, отписка — кнопкой
под каждым сообщением, `/stop` или блокировкой бота.

- **Ученику** (без аккаунта): тренажёр → Профиль → «Напоминания в Telegram» → бот →
  «Запустить». Напоминание около выбранного часа (16–20, по умолчанию 19:00), только
  если сегодня ещё не занимался; после 3 дней простоя — на 6-й, 9-й, 12-й, на 15-й
  прощальное, дальше тишина. Плюс новое задание репетитора и срок сегодня/завтра.
- **Родителю**: студия → ученик → «Отчёты родителю в Telegram» → ссылка на 7 дней.
  Отчёт каждое воскресенье около 18:00 и одно сообщение на 3-й день без занятий.
  Работает, пока у репетитора активен тариф (у старых наборов без аккаунта — всегда).
- **Репетитору**: студия → «Подключить Telegram» (ссылка на час). `/dz` — задание в три
  нажатия; сообщение, если новый ученик не может присоединиться (бесплатный лимит),
  и за 2 дня до конца пробного, за 3 и 1 день до конца оплаты, на следующий день после.
- **Владельцу**: `/notify` — сколько подписок и чатов.

Включение (один раз, после деплоя):
1. В `wrangler.jsonc` добавить `"triggers": { "crons": ["*/5 * * * *"] }` (и `[triggers]
   crons = ["*/5 * * * *"]` в `worker/wrangler.toml`) — только с согласия владельца.
   Проверка: Cloudflare → Workers → econcards → Settings → Trigger Events.
2. Открыть `https://<адрес>/tg/setup?key=<TG_SECRET>` ещё раз: вебхук получит
   `my_chat_member` и `max_connections: 1`, команды для всех (`/settings`, `/stop`, `/dz`,
   `/help`) и отдельно для владельца, описание бота.
3. Необязательно: переменная `SITE_URL` — адрес сайта для ссылок в сообщениях
   (по умолчанию `https://econcards.kqrulev.workers.dev`).

Как устроено (важно при правках):
- `nt:list` — один индекс всех подписок. Пишет его **только вебхук бота**, синхронно
  до ответа Telegram (при `max_connections: 1` обновления идут по одному); при 429 —
  один повтор через 1,1 с, но не чаще раза в 10 с, и не больше 3 записей в минуту от одного
  чата (в памяти изолята): иначе один чат задерживал бы всю очередь, и вход через Telegram
  тоже. Включённая заново после отключения подписка получает новый `i`. Сайт отключает подписки отметками `nt:x:<s|r>:<набор>:<ученик>`,
  cron — списком `nt:gone`; вебхук выбрасывает их при следующей записи.
- Ссылки в бота (`s_`, `r_`, `t_`) — не ключи KV, а подпись HMAC на `TG_SECRET`.
  Смена `TG_SECRET` гасит невыданные ссылки, подписки остаются. В `r_` (её пересылают
  родителю) sid ученика скрыт маской HMAC. Кнопки бота ученику ведут на `?t=<набор>&s=<sid>`:
  пустой прогресс на новом устройстве берёт этот sid, приложение сразу убирает его из адреса.
- Cron: каждая подписка привязана к одному 5-минутному слоту своего местного дня. За
  запуск — не больше 60 подписок и 45 сообщений; в большинстве запусков 2 чтения KV.
  Отправка сообщения ничего не пишет в KV; `list` и `pack:<id>` cron не читает.
- Задание — `hw:<набор>`, приходит ученику внутри `GET /packs/:id` и исчезает само через
  месяц после срока; после «Снять задание» время рассылок сутки лежит в `hwp:<набор>`
  (лимит 3 рассылки в сутки). Тема задания должна быть в опубликованном наборе. Название и
  репетитор набора — в метаданных `pack:<id>`; в сводку ученика (`POST /progress`) сервер
  пишет их оттуда, а не из запроса.
- Ошибки — в Logs (Live) с префиксом `notify`; `notify overflow` — в слот не влезли все.

Проверка локально: `npx wrangler dev --test-scheduled`, затем
`curl 'http://localhost:8787/__scheduled?cron=*/5+*+*+*+*'`.
